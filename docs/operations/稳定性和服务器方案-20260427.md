## 业务接口压测

测试方式：

- 本地临时 API：`127.0.0.1:8896`
- 临时 SQLite：`D:/姚律师临时测试/business_load.db`
- 每个接口请求量：160 次
- 并发：16

结果：

| 接口 | 错误 | RPS | p50 | p95 | p99 | 最大 |
|---|---:|---:|---:|---:|---:|---:|
| `/v1/plans` | 0 | 96.08 | 154.91ms | 184.87ms | 196.11ms | 202.62ms |
| `/v1/auth/me` | 120 | 90.62 | 158.45ms | 246.44ms | 280.54ms | 288.84ms |

`/v1/auth/me` 的错误是 `429 Rate limit exceeded`，不是服务异常。当前默认限流是每用户每 60 秒 40 次请求，压测超过后被拦截。

结论：单用户猛刷会被限流，符合预期。正式上线应把限流从内存迁到 Redis，避免多 worker 时限流不一致。

## 免费临时上线方案

多 agent 交叉验证后的推荐：

```text
Render Free Web Service + Neon Free Postgres
```

原因：

- Render 免费后端能跑 FastAPI。
- Neon Free 不需要信用卡，超限暂停，不自动扣费。
- Koyeb 免费 Web 虽可用，但需要绑卡；Koyeb 免费数据库每月只有 5 小时 active time，不适合姚律师业务。
- Render 自带免费 Postgres 30 天到期，不适合保存真实数据。

执行云端创建前必须人工确认，不自动操作。

## 4核4G 美国服务器判断

结论：

```text
4核4G 美国服务器可以跑 MVP 和早期 100 个注册用户，但不要理解成 100 人同时高强度 AI 咨询。
```

建议早期同机部署：

- Caddy：自动 HTTPS 和反向代理
- FastAPI：2 个 worker 起步
- Postgres：本机 Docker volume，内存保守配置
- Redis：先用于限流/队列
- H5 静态文件：Caddy 直接托管
- 管理后台：低频访问可同机，后续再拆

美国服务器风险：

- 中国大陆访问可能慢，晚高峰抖动明显。
- 如果主要用户在国内，香港、日本、新加坡通常比美国更适合。
- 微信小程序请求域名必须配置 HTTPS 合法域名。

升级信号：

- 内存长期超过 75%
- 非 AI 接口 p95 超过 500ms
- AI 同时请求超过 20-30
- 数据库连接池频繁超时
- 磁盘超过 70%
- DAU 到 300-500 或开始稳定付费

## 算力中转站判断

4核4G 可以做早期 API 转发/中转，不可以做真正大模型推理。

早期建议：

1. 先做内部 AI 网关，只服务姚律师产品。
2. 对外销售算力前，必须独立出算力中转站。
3. 律师业务和算力业务至少要做到同机隔离：不同域名、不同服务、不同数据库/表空间、不同日志、不同密钥。

必须具备：

- 用户 API Key 哈希存储
- 上游 Key 加密和轮换
- 用户额度账本
- Redis 限流
- 日志脱敏
- 供应商路由和熔断
- 支付/退款/充值流水
- 风控封禁

不要做：

- 不要把上游 API Key 发给客户
- 不要把律师咨询内容写进算力网关日志
- 不要承诺无限量或永不断
- 不要在供应商条款不允许的情况下转售算力

## 下一步建议
